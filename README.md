# OpenProject Timesheet Sync

เครื่องมือ sync ชั่วโมงทำงานจากไฟล์ Excel เข้า OpenProject ผ่าน REST API v3
เป็นแอป Windows เดสก์ท็อปจริง (PySide6/Qt — ไม่มี local web server, ไม่มี browser engine)
มีตาราง preview ให้ตรวจสอบ/แก้ไข/เลือกหรือสร้าง Work Package ก่อนบันทึกจริง
เพื่อลดโอกาสกรอก Work Package ผิด บันทึกซ้ำ หรือกรอกชั่วโมงผิดพลาด

## ติดตั้ง

```bash
python -m venv .venv
.venv/Scripts/activate   # Windows (PowerShell: .venv\Scripts\Activate.ps1)
pip install -r requirements.txt
```

คัดลอก `config.example.yaml` เป็น `config.yaml` แล้วกรอกข้อมูลของจริง:

```bash
cp config.example.yaml config.yaml
```

- `openproject.url` — URL ของ OpenProject instance (ควรกรอกไว้)
- `openproject.api_key` — **ไม่จำเป็นต้องกรอกในไฟล์นี้ก็ได้** — `app.py` (หน้าต่างแอป) เปิดหน้า login
  ให้กรอกเองทุกครั้งที่เปิดโปรแกรมเสมอ (ดู API key จาก My Account > Access tokens) ถ้ามี url/api_key
  ในไฟล์นี้อยู่แล้วฟอร์มจะกรอกให้ล่วงหน้า แต่ยังต้องกดยืนยัน login เอง — ติ๊ก "จำไว้" ตอน login เพื่อบันทึก
  กลับไฟล์นี้อัตโนมัติ (สะดวกไม่ต้องพิมพ์ใหม่ครั้งถัดไป) — ส่วน `sync_timesheet.py` (CLI) ยังต้องมี
  ทั้ง url และ api_key ในไฟล์นี้เสมอ เพราะรันแบบไม่มีคนตรวจ ไม่มีหน้า login ให้กรอกทีหลัง
- `activity_mapping` — (ไม่บังคับ) แม็ปชื่อกิจกรรมในคอลัมน์ `activity` ของ Excel ไปยัง id ของ activity ใน
  OpenProject ใช้เป็นค่าตั้งต้นให้ dropdown "กิจกรรม" ในตารางเท่านั้น — ไม่ได้แม็ปไว้ก็เลือกเองในแอปได้
  (แอปดึงรายชื่อ activity จริงจากเซิร์ฟเวอร์มาให้อัตโนมัติ) แต่ `sync_timesheet.py` (CLI) ยังต้องพึ่ง mapping นี้เสมอ
- `user_mapping` — (ถ้าต้องบันทึกชั่วโมงแทนผู้ใช้คนอื่น) แม็ปอีเมล -> user id ใน OpenProject; ถ้าไม่แม็ป จะบันทึกในนามเจ้าของ API key
- `excel.columns` — ชื่อคอลัมน์จริงในไฟล์ Excel ของคุณ ถ้าใช้ `timesheet_template.xlsx` ไม่ต้องแก้

## รูปแบบไฟล์ Excel

ใช้ `timesheet_template.xlsx` เป็นต้นแบบ มีคอลัมน์:

| คอลัมน์ | ความหมาย |
|---|---|
| `date` | วันที่ทำงาน |
| `hours` | จำนวนชั่วโมง |
| `activity` | ชื่อกิจกรรม ใช้เลือก activity ตั้งต้นให้แถวนั้น (ตรงกับ key ใน `activity_mapping` หรือชื่อ activity บน OpenProject ตรงๆ ก็ได้ ไม่ตรงก็เลือกเองในตาราง) |
| `wp_mode` | `existing` = ใช้งานเดิม, `new` = ให้แอปสร้าง Work Package ใหม่ (พิมพ์ `เดิม`/`ใหม่` ก็ได้) **เว้นว่างได้** — แอปเดาให้: มี `new_subject` = สร้างใหม่, มี `wp_id` = งานเดิม |
| `wp_id` | เลข Work Package (โหมด `existing`) เว้นว่างได้ถ้ายังไม่รู้ — ไปค้นหาในแอป |
| `new_project` | โปรเจกต์ที่จะสร้างงานใหม่ (โหมด `new`) ใส่ชื่อเต็มหรือเลข id ก็ได้ ชื่อต้องตรงทั้งชื่อ |
| `new_subject` | ชื่อ Work Package ที่จะสร้าง (โหมด `new`) |
| `comment` | หมายเหตุ (ไม่บังคับ) |
| `user_email` | อีเมลเจ้าของชั่วโมงนี้ (ไม่บังคับ ใช้กับ `user_mapping`) |
| `synced` | ระบบจะติ๊กเป็น `True` เองหลัง sync สำเร็จ — อย่าแก้มือ |
| `sync_note` | ระบบจะเขียนผลลัพธ์/error กลับมาที่นี่ — ใช้ debug |

`wp_mode` / `new_project` / `new_subject` เพิ่มเข้ามาทีหลัง — **ไฟล์เก่าที่ไม่มี 3 คอลัมน์นี้ยังใช้ได้ปกติ**
(ทุกแถวถือเป็นโหมด `existing` เหมือนเดิม) ดูตัวอย่างครบทุกเคสได้ที่ `timesheet_sample.xlsx`

## ใช้งานผ่านแอป (แนะนำ — มีคนตรวจก่อนส่ง)

```bash
python app.py
```

เปิดหน้าต่างแอปเดสก์ท็อปจริงทันที (หรือ `--file timesheet.xlsx --config config.yaml` เพื่อให้หน้าต่าง
เลือกไฟล์เปิดค้างที่ไฟล์นั้นให้เลย) ลำดับที่เจอ:

1. **หน้า login (บังคับทุกครั้งที่เปิดโปรแกรม)** — กรอก OpenProject URL + API key, ระบบเรียก API แบบ
   read-only เพื่อตรวจว่า key ใช้ได้จริงก่อนเข้าหน้าถัดไป ถ้า `config.yaml` มี url/api_key อยู่แล้ว
   (เช่นเคยติ๊ก "จำไว้" ไว้ก่อนหน้านี้) ฟอร์มจะกรอกให้อัตโนมัติ แต่ยังต้องกดปุ่ม "เข้าสู่ระบบ" ยืนยันเองเสมอ
   ไม่มีการข้ามหน้านี้ไปเลย
2. **เข้าหน้าตารางหลักทันทีในสถานะว่าง** — ยังไม่ต้องเลือกไฟล์ Excel ตอนนี้ ไม่มีอะไรเด้งขึ้นมา
   ตารางจะขึ้นข้อความชวนให้กดปุ่ม **"⬆ อัปโหลดไฟล์ใหม่"** ที่มุมขวาบนเมื่อพร้อม กดแล้วจึงเปิด native
   file picker ของ Windows โดยเปิดค้างไว้ที่ไฟล์ `--file` ที่ระบุตอนรัน หรือไฟล์ล่าสุดที่เคยเลือก
   (ระบบจำไว้ที่ `last_file` ใน `config.yaml` อัตโนมัติทุกครั้งที่เลือกไฟล์สำเร็จ) ให้เลือกซ้ำได้เร็ว
3. **ตารางหลัก** — โหลดเฉพาะแถวที่ `synced` ยังไม่ `True` และพยายาม auto-match `wp_id` กับ
   Work Package จริงให้อัตโนมัติ:
   1. ตรวจสอบ/แก้ไขวันที่ ชั่วโมง หมายเหตุ ได้ทันทีในตาราง
   2. สำหรับแต่ละแถว เลือกโหมด **"เลือกงานเดิม"** (ค้นหาแล้วเลือกจากลิสต์) หรือ **"+ สร้างงานใหม่"** (เลือกโปรเจกต์ + กรอกชื่องาน + เลือกประเภทงาน)
      — ถ้าระบุ `wp_mode` / `new_project` / `new_subject` มาจาก Excel แล้ว แอปจะเปิดแท็บและกรอกให้เลย ไม่ต้องคลิกซ้ำ
   3. คอลัมน์ **"กิจกรรม"** เป็น dropdown ของ activity จริงบน OpenProject (แอปดึงมาให้เองหลัง login)
      ค่าตั้งต้นมาจากชื่อในคอลัมน์ `activity` ของ Excel — ถ้าจับคู่ไม่ได้ แถวนั้นจะเป็น "ต้องเลือก" จนกว่าจะเลือกเอง
   4. ใช้ปุ่ม **"ทั้งหมด" / "ต้องเลือก"** เพื่อกรองดูเฉพาะแถวที่ยังไม่ resolved และ **ช่องค้นหา**
      ข้างๆ เพื่อกรองจากชื่องาน หมายเหตุ วันที่ เลข Work Package หรือชื่อโปรเจกต์ (ใช้ร่วมกับปุ่มกรองได้ —
      ต้องเข้าเงื่อนไขทั้งคู่ถึงจะแสดง)
   5. เมื่อทุกแถว resolved ครบ (ทั้งงานและกิจกรรม) ปุ่ม **"ยืนยันและส่งเข้า OpenProject"** จะกดได้
   6. ถ้าติ๊ก **"ตรวจชื่องานซ้ำก่อนส่ง"** ไว้ (ตั้งต้นติ๊ก) ระบบจะค้นใน OpenProject ก่อนว่ามีงานชื่อ
      เดียวกันอยู่แล้วไหม เจอแล้วจะถามก่อนว่าจะส่งต่อหรือกลับไปสลับแถวเป็น "เลือกงานเดิม" —
      ยิง 1 คำขอต่อชื่องานที่ไม่ซ้ำกัน ถ้ามีหลายสิบแถวจะใช้เวลาสักครู่ ปิดได้ถ้าไม่ต้องการ
      (ส่วนชื่อที่ซ้ำกันเองภายในไฟล์เดียวกัน ระบบเตือนให้เสมอโดยไม่ต้องยิง API)
   7. หลังส่ง ระบบจะสร้าง Work Package ใหม่ (ถ้ามี) → บันทึกชั่วโมง → อัปเดต `synced`/`sync_note` กลับเข้าไฟล์ Excel ให้อัตโนมัติ

### แท็บ "ประวัติตามช่วงวันที่" — ดูย้อนหลังและปรับสถานะงาน

เลือกช่วงเดือน/วันที่แล้วกด **"ค้นหา"** เพื่อดึง time entry ของตัวเองมาแสดง (ไม่มีอะไรโหลดเองจนกว่า
จะกด) กรองต่อด้วยช่องค้นหา, dropdown รายชื่องาน และ **dropdown สถานะ** (แสดงเฉพาะสถานะที่มีอยู่จริงในผล
ค้นหา พร้อมจำนวน เช่น `COMPLETE (62)`) และกด **"⬇ ส่งออก Excel"** เพื่อบันทึกเป็นไฟล์รูปแบบเดียวกับ
ไฟล์อัปโหลด

ใต้ยอดรวมมีอีกสองบรรทัดที่คิดจากข้อมูลชุดเดียวกัน ไม่ได้ยิง API เพิ่ม:

- **ชั่วโมงแยกตามโปรเจกต์** — เดินตามตัวกรองเหมือนบรรทัดยอดรวม (มีโปรเจกต์เดียวจะซ่อนไป)
- **คำเตือนวันที่ลงไม่ครบ / ลงเกิน** — เทียบยอดรายวันกับ `worklog.hours_per_day` (ตั้งต้น 8)
  เช่น `⚠ ยังลงไม่ครบ 3 วัน: 2026-08-12 (พ) · 2026-08-20 (พฤ) · 2026-08-21 (ศ)` บรรทัดนี้
  **ไม่สนตัวกรอง** เพราะเป็นเรื่องของปฏิทินทั้งช่วงที่ค้นหา ไม่ใช่ของชุดที่กรองแล้ว

นอกจากดูย้อนหลัง แท็บนี้ยัง **ปรับสถานะ Work Package** ได้ด้วย — เพราะแอปสร้าง Work Package ใหม่
โดยไม่ระบุสถานะ งานที่เพิ่งสร้างจึงค้างอยู่ที่สถานะตั้งต้นของโปรเจกต์ (เช่น `TO DO`) และตารางหลัก
ของแท็บอัปโหลดก็มองไม่เห็นแล้วเพราะโหลดเฉพาะแถวที่ยังไม่ `synced`

- **คอลัมน์ "สถานะ"** — แต่ละแถวมี dropdown ของสถานะจริงบน OpenProject เลือกแล้วยืนยัน
  เพื่อเปลี่ยนเฉพาะงานนั้น ถ้างานเดียวกันมีหลายรายการชั่วโมงในช่วงที่ค้นหา ทุกแถวจะอัปเดตพร้อมกัน
- **ปรับทีเดียวทั้งชุด** — เลือก **"จากสถานะ"** (ตั้งต้น `TO DO`, เลือก "ทุกสถานะ" ได้) และ
  **"เป็น"** (ตั้งต้น `IN PROCESS`/`In progress` ตามชื่อที่ instance ใช้จริง) แล้วกด
  **"↻ ปรับสถานะงาน"** จะทำกับงานทั้งหมดที่แสดงอยู่ในตารางหลังกรอง — มีกล่องยืนยันบอกจำนวนและ
  ตัวอย่าง `#id ชื่องาน (สถานะเดิม → สถานะใหม่)` ก่อนเสมอ และข้ามงานที่อยู่สถานะปลายทางแล้วให้เอง
- **"เฉพาะงานที่ฉันสร้าง"** — ติ๊กไว้ตั้งต้น กันไม่ให้ไปแก้งานของเพื่อนร่วมทีมที่บังเอิญมีชั่วโมง
  ของเราผูกอยู่ (ติ๊กออกได้ถ้าตั้งใจจะแก้จริง)

### แท็บ "สรุปงาน" — จาก commit หรือไฟล์ `.md` ถึงตารางส่ง ในหน้าเดียว

แท็บนี้ยุบขั้นตอนที่เคยต้องทำข้าม 3 ที่ (ให้ Claude อ่าน git เขียนไฟล์สรุป `.md` → รัน `/timesheet`
แปลงเป็น `.xlsx` → กลับมากด "อัปโหลดไฟล์ใหม่" หาไฟล์นั้นอีกรอบ) ให้จบในหน้าเดียว

เริ่มด้วยการเลือก **แหล่งข้อมูล** ที่ปุ่มสลับด้านบน — **"จาก git"** อ่าน commit เอง หรือ
**"จากไฟล์ .md"** เมื่อมีสรุปงานเขียนไว้แล้ว ตั้งแต่ขั้นตอนที่ 4 เป็นต้นไปทั้งสองทางใช้ของชุดเดียวกัน

#### โหมด "จาก git" — ไม่มี file dialog สักอัน

1. **เลือกช่วงวันที่** — พิมพ์เองหรือกดปุ่มลัด "วันนี้ / เมื่อวาน / สัปดาห์นี้ / เดือนนี้" และตั้ง
   **ชม./วัน** (ตั้งต้น 8) ไว้เป็นเป้าหมายให้ระบบตรวจว่าแตก task ครบไหม ท้ายแถวมีช่อง **โมเดล**
   ให้เลือกว่าจะใช้ตัวไหนแตก task (ดูตารางด้านล่าง) ค่าที่เลือกถูกจำลง `config.yaml` ให้เอง
2. **เลือก repo** — กด "+ เพิ่ม repo" เลือกโฟลเดอร์ (ต้องมี `.git` จริง) แล้วเลือก
   **โปรเจกต์ OpenProject** ของ repo นั้นจาก dropdown — รายชื่อมาจากที่ดึงไว้ตอน login
   จึงไม่ยิง API เพิ่ม รายการ repo กับโปรเจกต์ที่เลือกถูกบันทึกลง `config.yaml` ให้อัตโนมัติ
   ครั้งหน้าไม่ต้องตั้งใหม่ (ติ๊กเปิด/ปิดรายตัวได้ ไม่ต้องลบทิ้ง)
3. **"อ่าน git"** — อ่าน commit ของช่วงวันที่นั้น (ข้าม merge commit, กรองเฉพาะ commit ของเรา
   ด้วย `git config user.email` หรือ `worklog.authors` ถ้าตั้งไว้) แล้วบอกว่าพบกี่ commit กี่วัน
   ขั้นนี้เป็น git ล้วน ไม่เรียกอะไรนอกเครื่อง
4. **"ให้ Claude แตกเป็น task"** — ส่ง commit ที่อ่านได้เข้า `claude` แบบ headless เพื่อแตกเป็น
   task ละ 1–2 ชม. ให้ครบชั่วโมงเป้าหมายต่อวัน พร้อมเขียนสรุปงาน markdown มาด้วยในรอบเดียว
   ระหว่างรอมีตัวนับเวลาและปุ่ม **"ยกเลิก"** (กดแล้ว process ตายจริง) — **Claude ไม่ได้รับสิทธิ์
   ใช้ tool ใดๆ** แอปอ่าน git มาให้ครบแล้วส่งเป็นข้อความไปตรงๆ
5. **เช็คกับ OpenProject** — ยิงเองอัตโนมัติทันทีที่ได้ task มา (กดปุ่ม **"เช็คบน OpenProject"**
   เพื่อเช็คซ้ำได้หลังแก้ชื่องาน/โปรเจกต์) ถามสองเรื่อง เป็น **GET ล้วน ไม่สร้างไม่แก้อะไร**:
   - **มี Work Package ชื่อนี้อยู่แล้วไหม** ในโปรเจกต์ที่เลือก — เจอแล้วคอลัมน์ **"บน OpenProject"**
     ของแถวนั้นจะเลือก `#id` ไว้ให้ แถวนั้นจะ**ผูกกับงานเดิม ไม่สร้างใบใหม่** สลับกลับเป็น
     "สร้างใหม่" เองได้ถ้าตั้งใจสร้างซ้ำจริง และการเช็คซ้ำจะไม่ทับสิ่งที่เลือกเองไว้แล้ว
   - **วันนั้นลงชั่วโมงไปแล้วหรือยัง** — ขึ้นบรรทัดเตือนใต้ตาราง และแถวที่งานนั้นวันนั้น
     ลงชั่วโมงไปแล้วจะถูกย้อมสีส้มพร้อมบอกว่าลงไปกี่ชั่วโมง

   ยังไม่ได้ login หรือเช็คไม่สำเร็จก็ใช้แท็บต่อได้ตามปกติ ทุกแถวเป็น "สร้างใหม่" เหมือนเดิม
6. **ตรวจ/แก้ในตาราง** — แก้ได้ทุกช่อง (วันที่ ชั่วโมง ชื่องาน หมายเหตุ โปรเจกต์) เพิ่มแถว/ลบแถวได้
   แถบล่างสรุปชั่วโมงต่อวันแบบสด ครบพอดีขึ้นเขียว ไม่ครบขึ้นส้มพร้อมบอกว่าวันไหนขาดเท่าไร
   (**เตือนเฉยๆ ไม่บล็อก** — ต่างจาก CLI ที่หยุดเลย เพราะตรงนี้มีคนนั่งตรวจอยู่)
7. **"บันทึกสรุป .md"** (ถ้าต้องการเก็บไฟล์สรุป) และ **"ส่งเข้าตารางหลัก →"** — เขียน `.xlsx`
   ลง `worklog.output_dir` ให้เอง แล้วโหลดเข้าแท็บแรกทันที ไม่ต้องเลือกไฟล์ (ถ้ายังมีแถวที่
   ลงชั่วโมงซ้ำค้างอยู่ จะถามยืนยันก่อน)

#### โหมด "จากไฟล์ .md" — เมื่อสรุปงานมีอยู่แล้ว

สำหรับงานที่ไม่ได้มาจาก git (สรุปประชุม บันทึกที่พิมพ์เอง ไฟล์สรุปที่ Claude session อื่นเขียนไว้)
ต่างจากโหมด git แค่ที่มาของข้อมูล:

- กด **"เลือกไฟล์ .md"** อ่านไฟล์เข้ากล่องข้อความ หรือ **วาง/พิมพ์สรุปลงกล่องตรงๆ** ก็ได้ —
  เนื้อที่เห็นในกล่องคือสิ่งที่จะส่งให้ Claude แก้ก่อนกดได้ทุกเมื่อ (ไฟล์ต้นทางไม่ถูกแก้)
- เลือก **โปรเจกต์** ครั้งเดียวใช้กับทุกแถวที่ได้กลับมา (ไม่มี repo ให้แมป) แก้รายแถวในตาราง
  ผลลัพธ์ได้ทีหลังเหมือนเดิม — ไม่เลือกก็แตก task ต่อได้ แต่ต้องไปเลือกเองในตารางหลัก
- **วันที่ของแต่ละ task มาจากเนื้อในสรุป** ช่องช่วงวันที่ด้านบนเป็นแค่ค่าสำรองเมื่อในสรุปไม่มีวันที่
  ส่วน **ชม./วัน** ยังเป็นเป้าหมายจริงเหมือนโหมด git
- Claude ไม่ถูกขอให้เขียนสรุปกลับมา (มีอยู่แล้ว) ปุ่ม **"บันทึกสรุป .md"** จะเก็บเนื้อในกล่อง —
  มีประโยชน์ตอนพิมพ์/วางสรุปเองโดยยังไม่มีไฟล์ต้นทาง
- ไฟล์ที่เลือกล่าสุดถูกจำไว้ที่ `worklog.last_summary_file` เพื่อเปิด dialog ที่โฟลเดอร์เดิม
  ครั้งหน้า **แต่ไม่โหลดเนื้อไฟล์ให้อัตโนมัติตอนเปิดแอป**

ผลลัพธ์คือแถวในตารางหลัก**มีโปรเจกต์และประเภทงานครบตั้งแต่เปิด** เหลือแค่ตรวจแล้วกด
"ยืนยันและส่งเข้า OpenProject" ส่วนแถวที่ผูกกับงานเดิมไว้แล้วจะขึ้น **"พร้อมส่ง" ทันที**
ไม่ต้องไปเลือก Work Package เองอีกรอบ

**ต้องมี `claude` (Claude Code) อยู่บนเครื่อง** — แอปหาจาก PATH เอง หรือระบุ path เต็มไว้ที่
`worklog.claude_path` ใน `config.yaml` ถ้าหาไม่เจอ แท็บยังเปิดใช้ปุ่ม "อ่าน git" ได้ตามปกติ
แค่ปุ่มแตก task จะกดไม่ได้พร้อมบอกเหตุผล และต้องมี `git` บน PATH ด้วย

#### เลือกโมเดล และทำไมมันเร็วขึ้น

ตัวเลขวัดจริงด้วย commit ตัวอย่างชุดเดียวกัน (1 วัน 3 commit เป้าหมาย 8 ชม.) ไม่ได้เดาจากขนาดโมเดล:

| โมเดล | เวลา | ราคา/ครั้ง | ผลที่ได้ |
|---|---|---|---|
| **Sonnet 5** (ค่าเริ่มต้น) | ~20 วิ | ~$0.031 | 5 task ครบ 8 ชม. อ้างไฟล์ถูก |
| **Opus 5** | ~23 วิ | ~$0.059 | 5 task หมายเหตุละเอียดที่สุด (มี +48/-12 ราย commit) |
| **Haiku 4.5** | ~46 วิ | ~$0.028 | 3 task ก้อนละ 3 ชม. — **ช้ากว่าและหยาบกว่า** เพราะไล่คิดยาวจน output token บานกว่าตัวอื่นหลายเท่า |

ค่าเริ่มต้นคือ **Sonnet 5** (`worklog.claude_model`) — เว้นว่างไว้ก็ได้ผลเดียวกัน ถ้าอยากปล่อยให้
`claude` CLI เลือกโมเดลเองให้เลือก "ใช้ค่าเริ่มต้นของ claude CLI" ใน dropdown (เก็บเป็น `"cli"`)

นอกจากเลือกโมเดลแล้ว คำสั่งที่ยิงเข้า `claude` ถูกตัดของที่งานนี้ไม่ได้ใช้ออกทั้งหมด
วัดกับ prompt ตัวอย่างได้ **44.7 วิ / $0.1375 → 16.0 วิ / $0.0341** (input token ลดราว 95%
output ลดราว 63%):

- `--safe-mode` ไม่โหลด `CLAUDE.md` / skill / plugin / hook / MCP ของเครื่องผู้ใช้ —
  auth กับการเลือกโมเดลยังทำงานปกติ (ต่างจาก `--bare` ที่บังคับใช้ `ANTHROPIC_API_KEY`
  อย่างเดียวและจะพังกับคนที่ login ผ่าน OAuth)
- `--tools ""` ตัดนิยาม tool ทิ้งทั้งชุด — เดิมโค้ดแค่ "ตั้งใจ" ไม่ให้ Claude ใช้ tool
  แต่นิยามยังถูกส่งไปกินโทเคนทุกครั้ง ตอนนี้บังคับจริง
- `--system-prompt` สั้นบรรทัดเดียวแทน system prompt ของ Claude Code ทั้งก้อน
- `--strict-mcp-config` ไม่แตะ MCP server ที่ตั้งไว้ (ไม่ต้องรอ start), `--no-session-persistence`
  ไม่เขียน session ทิ้งไว้ให้รก
- `--effort low` ตัวคุมความลึกในการคิด = ตัวแปรใหญ่สุดของเวลา ปรับได้ที่ `worklog.claude_effort`
  (`low` / `medium` / `high` / `xhigh` / `max`) — วัดแล้ว `low` ยังแตกครบชั่วโมงและอ้างไฟล์ถูก

ถ้า `claude` บนเครื่องเป็นเวอร์ชันเก่าจนไม่รู้จักธงเหล่านี้ ให้ตั้ง `worklog.claude_fast: false`
ใน `config.yaml` เพื่อกลับไปใช้คำสั่งชุดเดิม

แท็บนี้ยิง OpenProject เองแค่ตอนเช็คในข้อ 5 (`GET` รายการ Work Package กับ time entry ของตัวเอง)
**ไม่สร้างและไม่แก้อะไรบนเซิร์ฟเวอร์** ของจริงยังเกิดตอนกด "ยืนยันและส่งเข้า OpenProject"
ในแท็บแรกเหมือนเดิม

> คำสั่ง `/timesheet` เดิม (แปลงไฟล์ `.md` ที่มีอยู่แล้วเป็น `.xlsx`) ยังใช้ได้เหมือนเดิม
> ไม่ได้ถูกแทนที่ — แต่ไม่ใช่ทางเดียวอีกต่อไป โหมด "จากไฟล์ .md" ของแท็บนี้ทำเรื่องเดียวกันโดยไม่
> ต้องออกจากแอปและได้แถวที่มีโปรเจกต์ครบมาเลย

### แท็บ "สร้างไฟล์ Template" — กรอกไฟล์อัปโหลดให้เร็วขึ้น

แท็บนี้**ไม่ยิง OpenProject API เลย** เป็นแค่ตัวช่วยสร้างไฟล์ `.xlsx` รูปแบบเดียวกับไฟล์อัปโหลด
(ทุกแถวเป็น `wp_mode=new`) สร้างเสร็จแล้วต้องไปเปิดผ่าน "⬆ อัปโหลดไฟล์ใหม่" ในแท็บแรก
เพื่อเลือก/สร้าง Work Package จริงก่อนถึงจะส่งได้ มี 2 โหมด:

- **กรอกค่าเดียวทุกแถว** — วันที่/ชั่วโมง/กิจกรรม/โปรเจกต์ ชุดเดียวใช้กับทุกแถว พิมพ์ชื่องานบรรทัดละ 1 งาน
  เหมาะกับงานที่ลงวันเดียวกันหมด
- **ตารางรายแถว** — กำหนดวันที่/ชั่วโมง/หมายเหตุแยกกันได้ทุกแถว

ในโหมดตารางมีปุ่ม **"📋 วางจาก Excel"** สำหรับเพิ่มทีละหลายสิบแถว: คัดลอกช่วงเซลล์จาก
Excel/Google Sheets มาวางได้ตรงๆ คอลัมน์คั่นด้วย Tab ตามลำดับ

```
วันที่    ชั่วโมง    ชื่องาน    [โปรเจกต์]    [หมายเหตุ]
```

- 3 คอลัมน์แรกต้องมีเสมอ ส่วนโปรเจกต์กับหมายเหตุใส่หรือไม่ใส่ก็ได้
- วันที่รับ `YYYY-MM-DD`, `DD/MM/YYYY`, `DD-MM-YYYY`, `YYYY/MM/DD` — แปลงเป็น `YYYY-MM-DD` ให้เอง
- แถวหัวตารางกับบรรทัดว่างข้ามให้อัตโนมัติ
- บรรทัดที่อ่านไม่ได้จะถูกรายงานพร้อมเลขบรรทัด (ไม่หายเงียบ) แล้วเลือกได้ว่าจะเอาเฉพาะแถวที่อ่านได้ต่อไหม
- แถวที่วางเข้ามาจะไปอยู่ในตาราง แก้/ลบต่อได้ตามปกติก่อนกด "สร้างไฟล์ Template"

ถ้าไม่มี Tab ในบรรทัดเลยจะลองใช้คอมมาแทน — แต่ถ้ามี Tab อยู่แล้ว คอมมาที่อยู่ในชื่องานจะไม่ถูกแตกออก

ที่มุมขวาบนของหน้าตารางหลักมีปุ่ม **"⬆ อัปโหลดไฟล์ใหม่"** (เปิด native file picker เพื่อสลับไฟล์ โดยไฟล์เดิม
ยังแสดงอยู่ในตารางจนกว่าจะเลือกไฟล์ใหม่สำเร็จจริงๆ — ยกเลิกตอนไหนก็ได้ ไม่มีผลกับข้อมูลเดิม) และ
**"ออกจากระบบ"** (กลับไปหน้า login ใหม่ โดยไม่ปิดโปรแกรม)

แถวไหนล้มเหลว (network error, activity ไม่ตรง config, สร้าง Work Package ไม่สำเร็จ ฯลฯ) จะไม่กระทบแถวอื่น
ดูรายละเอียด error ได้ที่คอลัมน์ `sync_note` ในไฟล์ Excel

**หมายเหตุเรื่อง login**: เป็นแค่หน้าจอกรอก OpenProject API key ของตัวเอง (ตรวจสอบผ่าน OpenProject API จริง)
ไม่ใช่ระบบ user account/password แยกต่างหาก — เหมาะกับใช้ในเครื่อง/เครือข่ายภายในเท่านั้น ไม่มี session
timeout หรือการจำกัดสิทธิ์ใดๆ เพิ่มเติมจากที่ OpenProject เองมีอยู่แล้ว

## แพ็กเป็น .exe แจกจ่ายให้ทีม (ไม่ต้องลง Python)

สำหรับแจกให้เพื่อนร่วมทีมที่ไม่อยากติดตั้ง Python/venv เอง สามารถแพ็ก `app.py` เป็นไฟล์ `.exe`
เดียวจบด้วย [PyInstaller](https://pyinstaller.org/) — เปิดเป็น**หน้าต่างแอปเดสก์ท็อปจริง**
(เขียนด้วย [PySide6](https://doc.qt.io/qtforpython-6/)/Qt widgets ล้วนๆ ไม่มี local web server, ไม่มี
browser engine ใดๆ อยู่เบื้องหลังเลย) มีกรอบหน้าต่าง ปุ่ม minimize/maximize/close ของตัวเอง
ไม่ใช่แท็บเบราว์เซอร์ ไม่มี URL bar ไม่มีหน้าต่าง console ดำๆ ให้เห็น ไม่ต้องพิมพ์คำสั่งใดๆ

### วิธี build

```bash
build_exe.bat
```

หรือรันเองทีละคำสั่ง:

```bash
pip install -r requirements.txt pyinstaller
pyinstaller --onefile --windowed --noconfirm --name TimesheetSync ^
  --icon "assets\icon.ico" ^
  --add-data "assets;assets" ^
  app.py
```

ได้ไฟล์ `dist/TimesheetSync.exe` (ไฟล์เดียว รวม Python + PySide6/Qt + dependencies ทั้งหมดแล้ว)
มีไอคอนโปรแกรม (นาฬิกาจับเวลาสีเขียว, `assets/icon.ico`) ติดมาด้วย เห็นได้ทั้งบน taskbar, shortcut, และตอนติดตั้ง

ไม่ต้องมี WebView2 หรือ browser runtime ใดๆ บนเครื่องปลายทาง — Qt widgets วาดหน้าต่างเองทั้งหมด

### วิธีแจกจ่าย

ก็อปปี้ไฟล์เหล่านี้ไปไว้โฟลเดอร์เดียวกัน แล้วส่งทั้งโฟลเดอร์ (หรือ zip) ให้เครื่องอื่น/ทีม:

```
TimesheetSync.exe
TimesheetSyncCLI.exe   (ถ้าต้องการใช้กับ Task Scheduler ด้วย)
config.yaml            (ก็อปปี้จาก config.example.yaml แล้วกรอกข้อมูล OpenProject ให้เรียบร้อยก่อนแจก)
timesheet_template.xlsx
install.bat
uninstall.bat
```

### ตัวติดตั้งแบบ Setup Wizard จริง (แนะนำ)

สำหรับให้ความรู้สึกเหมือนติดตั้งโปรแกรมทั่วไป (มีหน้า Welcome → เลือกโฟลเดอร์ → เลือก task เสริม →
Ready to Install → progress bar → Finish) และขึ้นในรายการ **Windows Settings > Apps > Installed apps**
พร้อมถอนการติดตั้งได้จากตรงนั้นเหมือนโปรแกรมทั่วไป ใช้ [Inno Setup](https://jrsoftware.org/isinfo.php)
(ฟรี, open-source) แปลง `TimesheetSync.exe` + `TimesheetSyncCLI.exe` เป็น `TimesheetSync-Setup-<เวอร์ชัน>.exe` ไฟล์เดียว

ติดตั้ง Inno Setup (ทำครั้งเดียวบนเครื่องที่ใช้ build):

```bash
winget install JRSoftware.InnoSetup
```

จากนั้น build:

```bash
build_exe.bat
build_sync_exe.bat
build_installer.bat
```

ได้ไฟล์ `installer_output\TimesheetSync-Setup-<เวอร์ชัน>.exe` (เลขมาจาก `version.py` เช่น
`TimesheetSync-Setup-1.2.2.exe` — แต่ละรุ่นเป็นคนละไฟล์ ไม่เขียนทับกัน) — ไฟล์เดียว แจกให้ใครก็เปิดติดตั้งได้ทันที
**ไม่ต้องสิทธิ์ Admin** (ติดตั้งที่ `%LocalAppData%\TimesheetSync` ต่อผู้ใช้), มี shortcut ที่ Desktop/Start Menu,
มีตัวถอนการติดตั้ง (`Uninstall TimesheetSync` ใน Start Menu หรือถอนจาก Windows Settings ก็ได้)

ถ้ามี `config.yaml` ที่กรอกข้อมูลจริงแล้วอยู่ในโฟลเดอร์โปรเจกต์ตอน build จะถูกฝังเข้าไปใน Setup.exe ให้เลย
(พนักงานเปิดใช้งานได้ทันทีไม่ต้องตั้งค่าเอง) — ถ้าไม่มีจะฝัง `config.example.yaml` ไปแทน แล้วเตือนให้ตั้งค่าตอนติดตั้งเสร็จ

### ติดตั้งบนเครื่องอื่นแบบไม่ต้อง build เอง (install.bat)

ถ้าไม่อยากลง Inno Setup หรือแค่ต้องการทางลัดเร็วๆ ไม่ต้องมี wizard ก็ใช้ **`install.bat`** แทนได้ —
เป็นสคริปต์ธรรมดา ทำงานคล้ายกัน (คัดลอกไปที่ `%LOCALAPPDATA%\TimesheetSync`, สร้าง shortcut) แต่ไม่มีหน้า wizard
และไม่ขึ้นในรายการ Apps ของ Windows (ถอนการติดตั้งด้วย `uninstall.bat` แทน)

ที่เครื่องปลายทาง ดับเบิลคลิก **`install.bat`** — สคริปต์จะ:
1. คัดลอกไฟล์โปรแกรมไปไว้ที่ `%LOCALAPPDATA%\TimesheetSync` (ติดตั้งเฉพาะผู้ใช้นั้น **ไม่ต้องสิทธิ์ Admin**
   จึงใช้ได้แม้เครื่องบริษัทที่ล็อกสิทธิ์ผู้ใช้ทั่วไปไว้)
2. สร้าง shortcut ที่ Desktop และ Start Menu ชื่อ "TimesheetSync"
3. ถ้ามี `config.yaml` เดิมติดตั้งอยู่แล้ว จะไม่ทับ (กันข้อมูล API key เดิมหาย) — ถ้ายังไม่มีจะคัดลอก
   `config.example.yaml`/`config.yaml` จากโฟลเดอร์ที่รัน `install.bat` ให้แทน

หลังติดตั้ง เปิดโปรแกรมได้จาก shortcut บน Desktop หรือ Start Menu ได้เลยโดยไม่ต้องกลับมาที่โฟลเดอร์ติดตั้งเดิม
ถอนการติดตั้งด้วย **`uninstall.bat`** (จะลบโฟลเดอร์ที่ติดตั้งและ shortcut ทั้งหมด — สำรอง `config.yaml`
ไว้ก่อนถ้ายังต้องใช้ข้อมูลนั้นต่อ)

ไม่อยากติดตั้งแบบมี shortcut ก็ยังรัน `TimesheetSync.exe` ตรงๆ จากโฟลเดอร์ที่แตกไฟล์ไว้ได้ตามปกติ —
ทั้ง Setup.exe และ install.bat เป็นแค่ทางเลือกเสริมให้ใช้งานสะดวกขึ้นบนเครื่องที่ตั้งใจใช้ประจำ

ผู้ใช้ปลายทางแค่ **ดับเบิลคลิก `TimesheetSync.exe`** (หรือ shortcut หลังติดตั้ง) — โปรแกรมจะ:
1. เปิดหน้าต่างแอป Timesheet Sync ทันที ไม่ต้องมี `config.yaml` มาก่อนก็ได้
2. เจอหน้า login ให้กรอก OpenProject URL + API key เองเสมอ (ฟอร์มกรอกล่วงหน้าให้ถ้ามีข้อมูลใน `config.yaml`)
3. login เสร็จเข้าหน้าตารางว่างๆ ยังไม่ต้องเลือกไฟล์ Excel — กด "⬆ อัปโหลดไฟล์ใหม่" เองเมื่อพร้อม
4. ปิดได้โดยกดปุ่มปิด (X) ที่มุมขวาบนของหน้าต่างแอปตามปกติ

ยังใช้ `--file` / `--config` เป็น argument ตอนรัน `.exe` จาก command line ได้เหมือนเดิม เช่น
`TimesheetSync.exe --file timesheet.xlsx` จะไม่โหลดไฟล์ให้อัตโนมัติ แต่เปิดหน้าต่างเลือกไฟล์ค้างไว้ที่
ไฟล์นั้นให้ (ถ้าต้องการ sync แบบไม่ต้องกดอะไรเลย ใช้ `TimesheetSyncCLI.exe` ในหัวข้อถัดไปแทน)

### แพ็ก sync_timesheet.py (CLI สำหรับ cron/Task Scheduler) เป็น .exe ด้วย

```bash
build_sync_exe.bat
```

หรือรันเอง:

```bash
pip install pyinstaller
pyinstaller --onefile --noconfirm --name TimesheetSyncCLI sync_timesheet.py
```

ได้ไฟล์ `dist/TimesheetSyncCLI.exe` — เป็น console app ล้วนๆ ไม่มี GUI ใดๆ (ไม่มีหน้าต่างเลือกไฟล์)
เหมาะกับตั้งให้รันอัตโนมัติผ่าน **Windows Task Scheduler** โดยไม่ต้องมีคนเฝ้าหน้าจอ เช่น:

```
TimesheetSyncCLI.exe --file "C:\shared\timesheet.xlsx"
```

ต้องมี `config.yaml` อยู่ข้าง `.exe` เช่นเดียวกับ `TimesheetSync.exe` (หรือระบุ `--config` เอง)
พฤติกรรม sync เหมือนเดิมทุกประการ: sync เฉพาะแถวที่มี `wp_id` ถูกต้องแล้วเท่านั้น,
exit code `0` = สำเร็จหมด, `1` = มีแถวถูกข้าม/ล้มเหลว (เอาไปเช็คใน Task Scheduler ว่างานล้มเหลวได้)

**สรุปว่าตอนนี้มี 2 exe แยกกัน:**
| ไฟล์ | ใช้ที่ไหน | ใครใช้ |
|---|---|---|
| `TimesheetSync.exe` | ดับเบิลคลิกเอง มีตารางให้ตรวจก่อนส่ง | พนักงานทั่วไป |
| `TimesheetSyncCLI.exe` | ตั้งรันอัตโนมัติผ่าน Task Scheduler ไม่มีคนตรวจ | แอดมิน/ระบบอัตโนมัติ (เฉพาะแถวที่มี `wp_id` ถูกต้องแล้ว) |

## ใช้งานผ่าน CLI (สำหรับรันอัตโนมัติ เช่น cron)

```bash
python sync_timesheet.py --file timesheet.xlsx --config config.yaml
```

โหมดนี้ไม่มีคนตรวจก่อน จึงจะ sync **เฉพาะแถวที่มี `wp_id` กรอกไว้แล้วและตรงกับ Work Package จริง**
แถวที่ยังไม่มี `wp_id` หรือ `wp_id` ไม่ถูกต้อง จะถูกข้าม พร้อมบันทึกเหตุผลไว้ที่ `sync_note`
ให้ไปจัดการ (เลือก/สร้างงาน) ผ่านแอปแทน

Exit code เป็น `0` เมื่อทุกแถวสำเร็จ, เป็น `1` เมื่อมีแถวถูกข้าม/ล้มเหลว (เหมาะกับใช้เช็คใน cron/CI)

## แก้ปัญหาบนเครื่องผู้ใช้ปลายทาง

### ขั้นแรกเสมอ: กดปุ่ม "ตรวจสอบระบบ"

อยู่ที่หน้าเข้าสู่ระบบ ใต้ปุ่มเข้าสู่ระบบ กดแล้วรอสักครู่จะได้รายงานที่ไล่ตั้งแต่ path ของไฟล์ตั้งค่า,
ตัวแปรสภาพแวดล้อมที่มีผลต่อการเชื่อมต่อ, ชุดใบรับรองที่ใช้, DNS, TCP, TLS ไปจนถึงการเรียก API จริง
กด **คัดลอกทั้งหมด** แล้วส่งให้ผู้ดูแลได้เลย — **ในรายงานไม่มี API key**

ถ้าเปิดหน้าต่างโปรแกรมไม่ขึ้นเลย ใช้ตัว CLI แทนได้ ไม่ต้องมี `config.yaml`:

```powershell
& "$env:LOCALAPPDATA\TimesheetSync\TimesheetSyncCLI.exe" --diagnose
```

### ไฟล์ log

เขียนอัตโนมัติที่ `logs\timesheetsync.log` ข้างตัวโปรแกรม (ปกติคือ
`%LOCALAPPDATA%\TimesheetSync\logs\`) เก็บย้อนหลัง 3 ไฟล์ ไฟล์ละ 1 MB มี traceback เต็มของทุก
ข้อผิดพลาด และ **ไม่มี API key** เปิดดูในโปรแกรมได้จากปุ่ม "ดูรายละเอียดทางเทคนิค" ที่โผล่ขึ้นมา
เวลาเข้าสู่ระบบไม่สำเร็จ

> ไฟล์เป็น UTF-8 ไม่มี BOM — ถ้าเปิดด้วย `Get-Content` เฉย ๆ ใน Windows PowerShell ภาษาไทยจะเพี้ยน
> ให้ใส่ `-Encoding UTF8` (Notepad กับหน้าต่างในแอปอ่านถูกอยู่แล้ว)

### อาการที่เคยเจอจริง

| อาการ | สาเหตุ |
|---|---|
| `SSLCertVerificationError` ทั้งที่ Chrome เปิดเว็บเดียวกันได้ | เครื่องตั้ง `REQUESTS_CA_BUNDLE` / `SSL_CERT_FILE` ไว้ (เช่นเคยใช้ mitmproxy) ค่าพวกนี้ **แทนที่** ชุดใบรับรองมาตรฐานทั้งก้อน ไม่ใช่เพิ่มเข้าไป — ตัวโปรแกรมกันไว้แล้วโดยระบุชุดใบรับรองของตัวเองตรง ๆ แต่รายงานตรวจสอบระบบจะติดธง `[warn]` ให้เห็น |
| ต่อไม่ติด ทั้งที่ URL ถูก | `HTTPS_PROXY` / `HTTP_PROXY` ค้างอยู่ใน environment ของผู้ใช้ ทั้งที่ Windows ตั้งเป็นต่อตรง — เบราว์เซอร์ไม่อ่านตัวแปรพวกนี้ แต่โปรแกรมที่ใช้ไลบรารีมาตรฐานอ่าน |
| ตั้งค่าแล้วโปรแกรมไม่รับรู้ | โปรแกรมอ่าน environment ตอนเปิดเท่านั้น และไอคอนบน Desktop สืบทอด environment เก่าจากตอน log on — ต้อง log off / log on ใหม่ |

## ข้อจำกัดที่รู้อยู่แล้ว (ยังไม่ทำในเวอร์ชันนี้)

- ไม่รองรับหลายคนแก้ไฟล์ Excel เดียวกันพร้อมกัน (concurrent edit)
- การเตือน duplicate work package เป็นแค่**คำเตือน ไม่ได้บล็อก** — ถ้ากด "ส่งต่อไปเลย" ระบบจะสร้างงานใหม่ซ้ำอีกอันจริงๆ
  (และเทียบเฉพาะชื่อที่ตรงกันเป๊ะเท่านั้น ชื่อที่คล้ายกันแต่ไม่เหมือนจะไม่ถูกจับ)
- ตอนสร้าง Work Package ใหม่ยังไม่ได้ระบุสถานะ — ได้สถานะตั้งต้นของโปรเจกต์เสมอ ต้องไปปรับเองที่แท็บ "ประวัติตามช่วงวันที่"
- **workflow ของ OpenProject กำหนดเป็นราย type/role** สถานะปลายทางบางตัวจึงย้ายไปไม่ได้ และชื่อสถานะ
  ก็ตั้งเองได้ในแต่ละ instance (เช่นบางที่ใช้ `IN PROCESS` ไม่ใช่ `In progress`) แถวที่ย้ายไม่ได้จะขึ้น
  `no valid transition exists...` เป็น error รายตัว ไม่ทำให้ทั้งชุดล้ม — ดูสถานะที่ย้ายได้จริงได้จากหน้า
  Work Package บนเว็บ OpenProject
- คำเตือน "ยังลงไม่ครบ" นับเฉพาะ **จันทร์–ศุกร์** และเฉพาะ **วันที่ผ่านไปแล้ว** (วันนี้ยังลงไม่เสร็จ
  เป็นเรื่องปกติ) — ไม่มีปฏิทินวันหยุดราชการ วันหยุดที่ไม่ได้ลงอะไรไว้เลยจึงขึ้นเป็น "ขาด" ด้วย
  (ลงวันลาเป็น Work Package ไว้ก็จะไม่ถูกนับว่าขาด) ส่วน "ลงเกิน" นับทุกวันรวมเสาร์-อาทิตย์
  เพราะชั่วโมงที่เกินไปแล้วไม่ได้ถูกต้องขึ้นเองทีหลัง
- ไม่มีปุ่ม Undo สำหรับการปรับสถานะ — ถ้าเปลี่ยนผิดต้องเลือกสถานะเดิมกลับเอง
- หน้า login เป็นแค่ช่องกรอก API key ของตัวเอง ไม่มี user account/password/session timeout แยกต่างหาก — เหมาะกับใช้ในเครื่อง/เครือข่ายภายในเท่านั้น
- รันได้ทีละไฟล์ Excel ต่อการเปิดโปรแกรมหนึ่งครั้ง (สลับไฟล์ได้ผ่านปุ่ม "⬆ อัปโหลดไฟล์ใหม่" โดยไม่ต้องปิดโปรแกรม)
- ไม่ได้ทำ responsive สำหรับมือถือ
- ไม่มี pagination (ใช้ปุ่มกรอง "ต้องเลือก" ช่วยแทนถ้าแถวเยอะ)
